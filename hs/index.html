hs — hotkey scripts

A script is a plain text file bound to a key. Every non-empty line is one step, executed top to bottom on the client tick. Steps can run client commands, walk, press keys, type in chat, move the camera and wait. This page is the full reference for every command, step and key name.

quick start

.hs add /scripts/af1.txt R

Put the file in .minecraft/scripts/af1.txt and press R in game. Paths are relative to your Minecraft folder, a leading / is optional. Skip the key to bind on the next key you press (ESC cancels).

commands

Every command starts with your client prefix (. by default). .script and .scripts are aliases of .hs.

commandwhat it does
.hs add <file> [key]Binds a file to a key. Without key it waits for the next key press; ESC cancels. Mouse buttons work too (M1, M2, …).
.hs listPrints every bound script and its key.
.hs remove <file>Unbinds the script and forgets it (the file stays on disk).
.hs reloadRe-reads every bound file after you edit it. No restart needed.
.hs run <file>Runs a bound script once, right now, without waiting for its key.
.hs stopStops the script that is currently running.

The <file> argument tab-completes script files found under your game folder (.txt, .hs, .script), so .hs add /scripts/ + TAB lists what is in .minecraft/scripts.

script file

.vclip 0.3
*walk forward 0.3
@delay 10ms
.vclip -0.2
*walk backward 0.5
  • One step per line, executed in order; blank lines are skipped.
  • // starts a comment. # is not a comment — it sends a chat message.
  • Only one script runs at a time: starting another stops the previous one.
  • A running script stops by itself when you leave the world.
  • Binds are saved in haz/scripts.json; the files themselves are never modified.

steps

stepwhat it does
.command argsRuns any client command exactly as if typed in chat. The prefix is optional inside a script, so vclip 0.3 and .vclip 0.3 both work.
#textSends text to chat as a normal message (no command parsing). Example: #gg.
@delay <time>Pauses the script. Units: 10ms, 1s, 2t (ticks, 50 ms each) or a bare number of milliseconds. A delay shorter than a tick still costs one tick.
*walk <dir> <blocks>Moves you gradually in the direction you are facing: 0.2 blocks per tick until blocks is covered. Directions: forward, backward, left, right, up, down.
!<key>Presses a key, so whatever is bound to it fires (module toggles, keys, client binds). Examples: !B, !SPACE, !1, !F1, !LSHIFT, !M1 for mouse buttons. A script never re-triggers itself.
$camera freezePins the camera position where it is. The view still rotates with the mouse and you can keep moving — only the viewpoint stays behind.
$camera unfreezeEases the camera back to the player over ~300 ms (smooth, no snap) and hands it back to vanilla.

examples

clip and step

// up 0.3, forward 0.3, short pause, back down
.vclip 0.3
*walk forward 0.3
@delay 10ms
.vclip -0.2
*walk backward 0.5

freeze the view, move, release it

$camera freeze
.vclip 0.2
*walk forward 0.1
!B
@delay 15ms
*walk backward 0.0222
.vclip -0.07
$camera unfreeze

The freeze happens where the camera is at that line, so put it after the movement if you want the camera to stay at the new spot. @delay 15ms still costs one tick.

chat + key + command

#gg
!TAB
.toggle Phase
@delay 2t
!ENTER

notes

Key names follow Minecraft's own names: B, 1, SPACE, F1, TAB, ENTER, ESC, UP/DOWN/LEFT/RIGHT. SHIFT/CTRL/ALT map to the left variants, RSHIFT/RCTRL/RALT to the right ones.

Scripts run on the client tick, one step at a time; walks and delays pause the whole script. The first step runs on the tick after the key press.
