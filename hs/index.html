hs, hotkey scripts

a script is just a text file bound to a key. every line is one step and they run top to bottom on the client tick. a step can run a command, walk, press a key, say something in chat, move the camera or just wait. everything is on this page so you don't have to guess xD

quick start

.hs add /scripts/af1.txt R

drop the file in .minecraft/scripts/af1.txt and hit R in game. paths are relative to your minecraft folder, the / at the start is optional. skip the key and it binds to the next key you press (ESC cancels, in case you panic).

commands

every command starts with your client prefix (. by default). .script and .scripts do the same thing as .hs, use whatever you like.

commandwhat it does
.hs add <file> [key]binds a file to a key. no key? it waits for the next key you press (ESC cancels). mouse buttons work too (M1, M2, …).
.hs listshows every bound script and its key.
.hs remove <file>unbinds the script and forgets it (the file stays on your disk, relax).
.hs reloadre-reads all bound files after you edit them. no restart needed.
.hs run <file>runs a bound script once, right now, no key needed.
.hs stopstops the script that is running.

the <file> argument tab-completes script files in your game folder (.txt, .hs, .script), so .hs add /scripts/ + TAB shows what is in .minecraft/scripts.

script file

.vclip 0.3
*walk forward 0.3
@delay 10ms
.vclip -0.2
*walk backward 0.5
  • one step per line, runs in order. empty lines are skipped.
  • // starts a comment. # is not a comment, it sends a chat message, don't mix them up.
  • only one script runs at a time, starting another one stops the previous one.
  • a running script stops by itself when you leave the world.
  • binds are saved in haz/scripts.json, your files are never touched.

steps

stepwhat it does
.command argsruns any client command like you typed it in chat. the prefix is optional inside a script, so vclip 0.3 and .vclip 0.3 both work.
#textsends text to chat as a normal message (no command parsing). example: #gg.
@delay <time>waits. units: 10ms, 1s, 2t (ticks, 50 ms each) or a bare number of milliseconds. anything shorter than a tick still costs one tick.
*walk <dir> <blocks>moves you in the direction you are facing, 0.2 blocks per tick until blocks is covered. directions: forward, backward, left, right, up, down.
!<key>presses a key, so whatever is bound to it fires (module toggles, keys, client binds). examples: !B, !SPACE, !1, !F1, !LSHIFT, !M1 for mouse buttons. a script never triggers itself, so no infinite loops.
$camera freezepins the camera position where it is. you can still look around with the mouse and keep moving, only the viewpoint stays behind.
$camera unfreezesmoothly moves the camera back to the player over about 300 ms (no snap) and gives it back to vanilla.

examples

clip and step

// up 0.3, forward 0.3, short pause, back down
.vclip 0.3
*walk forward 0.3
@delay 10ms
.vclip -0.2
*walk backward 0.5

freeze the view, move, release it

$camera freeze
.vclip 0.2
*walk forward 0.1
!B
@delay 15ms
*walk backward 0.0222
.vclip -0.07
$camera unfreeze

the freeze happens where the camera is at that line, so put it after the movement if you want the camera to stay at the new spot. @delay 15ms still costs one tick.

chat + key + command

#gg
!TAB
.toggle Phase
@delay 2t
!ENTER

notes

key names are the same as in minecraft: B, 1, SPACE, F1, TAB, ENTER, ESC, UP/DOWN/LEFT/RIGHT. SHIFT/CTRL/ALT mean the left ones, RSHIFT/RCTRL/RALT the right ones.

scripts run on the client tick, one step at a time, and walks and delays pause the whole script. the first step runs on the tick after you press the key.
